### Why the seating chart, and the risk stated up front

The spec flagged this row with a warning: it **faces free generators already on
the open web**, so it needs an answer to "why not use the free one" baked in
rather than bolted on. **The new product shape is what makes that answer
available**, and it is one sentence: *the free ones make a chart; this one
remembers the term.*

Verified free alternatives, named honestly in the pack (see section c): Uplup's
free tier is a drag-and-drop chart maker with PNG export, up to 40 students per
chart, and view links for a substitute. Storyboard That saves charts to an
account. Kapwing and Creative Fabrica are general design tools with classroom
templates. **All of them are good at making a chart.** None of them is a record
of who sat where in October when you are deciding where they sit in February,
and all of them want the class list typed into somebody else's browser tab.

**Lane C note, one line:** this is a strong candidate for a Wednesday PD lab
later — every teacher in the room leaves with a chart for their own class, and
the "it has to remember" lesson is the whole of vibe coding in ten minutes.

### What the tool does out of the box, before the teacher reads a word

Double-click it and a **sample class of 24 is already seated** in a 6-by-4 grid,
with a term of history behind it so the "who has sat next to whom" view has
something in it. Nothing is blank, nothing has to be set up first.

| Out of the box | |
|---|---|
| A seating grid | rows and columns the teacher sets, desks draggable |
| A class list | names on the left, drag into a seat, drag back out |
| **Shuffle** | fills empty seats at random |
| **Shuffle, avoiding repeats** | the one free tools do not have — see below |
| A saved layout per class | name it "Period 3", switch between them |
| The history view | who has sat next to whom this term, as a simple count |
| Print | a clean chart that fits one page, names only |
| Save to file | the whole thing back as one HTML file |

**The feature the whole product rests on:** *Shuffle, avoiding repeats* reads the
stored history and seats the class so that, as far as the grid allows, nobody
sits next to somebody they have already sat next to this term. **When it cannot
satisfy that, it says so and names the pairs it had to repeat** rather than
failing silently. That refusal message is the single most important string in
the file and the factory should test it deliberately.

### The setup screen, and what it has to collect

Inside the file, reached from a **Set up this class** button. No code, no text
editor, ever.

1. **Class name** — free text, e.g. "Period 3". Used for the saved layout and
   the print header.
2. **Grid** — rows and columns, as two number inputs, with a live preview.
3. **The class list** — one name per line in a text area. **First names or
   initials, and the screen says so with the reason** rather than only a rule.
4. **Seats that are not seats** — click a cell to mark it blocked (a door, the
   teacher's desk, a cabinet). Blocked cells never receive a name.
5. **Reset the history** — a separate, confirmed button, for a new term.

### The AI drafting prompt, and the format it returns

On the setup screen, a copy button. Pasted into any AI chat tool, it returns a
class list the file parses on paste, in about thirty seconds.

```
I teach a class of <how many> students. Give me a list of <how many>
plausible first names for a class roster, one per line, nothing else
on each line. No surnames. No numbering. No commentary.
```

**Pipe-delimited is not needed here** — one name per line is the format, which
makes the parser simple and makes a teacher's own paste from a spreadsheet work
without any conversion. **The parser must name the lines it skipped and why**
(blank line, duplicate name, a line with a comma in it that looks like
"Surname, First"), the same as the Long Road and the Class Store.

**The instruction that always ships with it:** read them before you use them.
AI gets things wrong and the teacher owns the standards. For this tool there is
a second reason — **a drafted list is sample data, not your class**, and the
pack should be explicit that the teacher replaces it.

### The four change-it prompts, each changing one real thing

That is the entire vibe-coding lesson and it is one page, not a curriculum.

| # | What it changes |
|---|---|
| 1 | **Add a second row of desks at the back**, and make the grid remember the new size |
| 2 | **Color the seats by how long since that student last moved**, so the chart shows staleness at a glance |
| 3 | **Add a "keep these two apart" list** that the shuffle honors, and say what it does when it cannot |
| 4 | **Put the date on the print**, so a chart in a sub folder says when it was true |

Prompt 3 is the one worth running in front of a class or a staff room, because
the honest answer — *tell the user it could not* — is the whole lesson about
software that refuses rather than pretends.

## (c) PRICING — $12, licenses $6

Mid-band under the 09-23 shape. The Long Road is $12 and the Locked Room is $14;
this is a smaller tool than either and $12 is the honest place for it.

### What comparable tools actually cost, with real numbers

- **Classroomscreen.** Basic is free and its own pricing page caps it at **"Save
  three name lists."** Pro is **$3 a month, billed annually at $36 a year**, and
  what it adds includes **"Save unlimited name lists"**, saved screens, folders
  and 30 days of undo. Organization is **$525 a year per 25 licenses.**
- **Uplup seating chart maker.** Free tier, drag and drop, PNG export, **up to
  40 students per chart**, shareable view links.
- **Storyboard That, Kapwing, Creative Fabrica.** Free classroom seating-chart
  templates; the first saves to an account, the other two are general design
  tools.

### What the pack must say, and must not say

**Do not claim to undercut a free tool.** Several of these are free and good at
making a chart. The honest comparison has two halves and the pack prints both:

1. **What they do better.** They are more finished, they look nicer out of the
   box, and if all you need is a chart for the wall, use one of them and keep
   your twelve dollars. **Say that in the pack**, in those words.
2. **What is actually different.** A $36-a-year subscription is the shape of the
   paid answer in this category, and it recurs. **This is a file you own for
   $12 once**, it works with the wifi down, it cannot be switched off or
   repriced, and — the part no free generator does — **it remembers the term**,
   so a reshuffle in February knows about October.

**And the quiet one, which is the real difference:** every one of those tools
asks a teacher to type a class list into somebody else's browser tab. **This one
never sends it anywhere.** That is not a marketing line here; it is the design,
and section (d) is where the pack proves it.

## (d) DESIGN AND SAFETY — what this tool remembers, and where it lives

**The tier is decided by where the data lives and who can reach it, not by
whether names appear.** For this tool the honest answer is tier 2, and the pack
must not pretend otherwise just because the names are first names.

| | For this tool |
|---|---|
| **Tier 1 — build freely** | The grid, the row and column counts, the blocked cells, the class name, the print layout. Nothing about a child. |
| **Tier 2 — the teacher's own device** | **The class list, the seating history, and the saved file.** First names of real children, held in the browser's local storage and in any file the teacher saves. **Transmitted nowhere**, no account exists, no server holds a copy. |
| **Tier 3 — stop** | The same list in a shared drive, a cloud document, an email attachment, or pasted into a chatbot. **The moment it leaves the teacher's machine it is a different thing**, and the pack says that in those words. |

### The three things the pack has to state plainly

1. **Why first names or initials, with the reason rather than only the rule.**
   A seating chart needs to be readable at a glance from the front of the room,
   which first names already achieve. A surname adds nothing to the job and
   turns a classroom aid into something closer to a record. The setup screen
   says this where the teacher types, not only on a page they may skip.
2. **The history is the sensitive part, not the chart.** A printed chart is
   ordinary. **A term of who-sat-next-to-whom is a small social record of a group
   of children**, and it is the thing worth being deliberate about. Treat the
   saved file the way you treat a gradebook file: your machine, your business.
3. **Nothing is uploaded, and the pack should say how you can tell.** Open the
   file with the wifi off. Everything works. That is the demonstration, and it
   takes a teacher five seconds.

### And the spine sentence, which this build earns honestly

**Build it so the wrong thing is impossible, rather than so that you are
careful.** There is no upload in the file because there is no network call in the
file. A teacher does not have to remember a rule about not uploading a class
list, because the capability does not exist.

## WHAT THE TOOL MUST DO, FEATURE BY FEATURE, SO THE FACTORY CAN TEST IT

Drive every one of these in a browser before shipping. **Report what you drove
and what it returned.** Zero console errors.

1. **Opens by double-click**, offline, no install, sample class of 24 already
   seated with history behind it.
2. **Set up this class** opens the setup screen; class name, rows, columns, the
   name text area, blocked cells, and reset history all present.
3. **Paste a list** of names, one per line. **The parser names what it skipped
   and why** — test a blank line, a duplicate, and a "Surname, First" line.
4. **Drag a name into a seat**, drag it out, drag it to an occupied seat (the two
   swap). Test all three.
5. **Blocked cells never receive a name**, including from Shuffle.
6. **Shuffle** fills every empty, unblocked seat.
7. **Shuffle avoiding repeats** honors the history. **Then force it to fail** —
   a small grid and a long history — and confirm it **names the pairs it had to
   repeat** rather than failing silently or hanging.
8. **Layouts save per class**, switch between two, and both survive a reload.
9. **Print** produces one page with names and the class name, and no interface
   furniture on it.
10. **Save to file** hands back one HTML file; reopen it **in a clean browser
    profile** and the layout, the list and the history are all still there.
    Re-save on top and confirm **exactly one injected block**.
11. **Reset history** asks before it acts, and clears history without clearing
    the seating.

### Layout risk, which has caught something in six of the last seven builds

`.sheet` is a fixed 11in box with `overflow:hidden`. **An overfull page is
clipped silently and the footer paints straight through it** — a drop shipped
that way on 09-18 and four gates passed it. **`check_footer.py` is the fifth
gate and it is not optional.** When it fires, cut text; never shrink type.
Yesterday it caught the satellite's page 5 clipped by 54pt and `check_breaks.py`
caught a cover orphaning its stat row.

**Eyeball a contact sheet of all eight pages too.** The gates catch geometry and
spelling; your eyes catch meaning. A wrong-but-well-formed footer shipped on 29
pages because no gate looks for that.

## THE FAILURE MODES SPECIFIC TO THIS TOOL

Not generic ones. These are what a teacher hits with a seating chart.

1. **The grid does not match the room.** Real rooms have pods, a horseshoe, a
   bank of computers along one wall. **A rigid grid is the single most likely
   reason a teacher abandons this in the first two minutes.** Blocked cells are
   the answer and they must be obvious on the setup screen, not buried.
2. **More students than seats.** It will happen on day one. The tool must say
   so in plain words and seat who it can, rather than silently dropping names.
3. **A name arrives mid-term.** Adding one student must not reset the history or
   the layout. Test this.
4. **The "avoid repeats" shuffle becomes impossible** as the term goes on — in a
   small class every pairing eventually exists. **This is not a bug and the pack
   must say so**, along with what the tool does instead.
5. **The teacher wants two charts for one class** — a normal one and a test one.
   Saved layouts cover it, but only if the pack says so; otherwise they assume
   one chart per class and leave disappointed.
6. **The printed chart comes out mirrored.** Whether the chart is drawn from the
   teacher's view or the students' is a real and genuinely confusing question.
   **Pick one, print which one it is on the page, and offer a flip** — prompt 4
   territory if it does not make the base build.
